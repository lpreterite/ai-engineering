# Task Issue 拆分与自包含规范

> 引用：`skills/goal-issue-lifecycle/SKILL.md` 步骤 6

## 拆分原则

- **时机**：Goal Issue `approved` 后，人类确认进入执行（planned），Agent 询问拆分粒度，**人类确认拆分方案后**才展开
- **粒度**：默认一个阻塞项对应一个 Task Issue；若阻塞项过大（>2 天 / 多个独立步骤 / 跨角色），可拆为多个 Task
- **关联必填**：每个 Task Issue 必须引用 Goal Issue 编号（`关联: #N`）

## 自包含原则

> **Task Issue 是自包含可执行指令包，不是指向 Goal Issue 的指针。**
> 脱离创建它的会话后，读者（人类或新 AI）应能仅凭 Issue 内容独立理解并执行，
> 无需回溯聊天记录或重建对话上下文。

## 六段式字段规范

```
## 背景与动机（为什么有这个任务）
- 来源：Goal Issue 阻塞项 N
- 触发决策/评论：<引用及摘要>
- 前置依赖：<已完成的先决条件>

## 目标（一句话说明完成什么）
- <完成这个任务要达到的状态>

## 任务（执行指令——具体动作）
- [ ] 动作 1
- [ ] 动作 2

## 验收标准（可验证）
- [ ] 条件 1
- [ ] 条件 2

## 关联（尽力内联，不只放链接）
- 目标: <Goal Issue 编号>（含验收标准要点摘要）
- 参考产出物: <文件路径>
- 关键决策: <评论引用 + 结论摘要>

## 完成定义（明确不做 / 边界）
- 不做: <明确排除的范围>
- 边界: <与其他任务的职责划分>
```

## 示例

```
## 背景与动机
- 来源：Goal #101 阻塞项 2
- 触发决策：[决策] 周报格式采用 Markdown（#101 评论 #2）
- 前置依赖：A-1 的模板已落盘

## 目标
实现周报汇总合并逻辑，支持 Markdown 格式输入。

## 任务
- [ ] 读取成员提交的 .md 文件
- [ ] 实现合并生成汇总文档

## 验收标准
- [ ] 3 份样例周报正确合并
- [ ] 汇总结果格式正确

## 关联
- 目标: #101（验收标准：汇总合并正确）
- 关键决策: Markdown 格式（#101 评论 #2）

## 完成定义
- 不做: 不做邮件通知模块（范围外）
- 边界: 仅汇总逻辑，模板入口在 B-1
```
