# 评论协议：决策 / 审计 / 改进

> 引用：`skills/goal-issue-lifecycle/SKILL.md` 步骤 2

## 原则

- 所有打磨阶段的讨论记录**以 Goal Issue 评论形式附着**
- 评论用前缀标识类型，便于检索与回溯
- 不贴原始聊天记录，只做**结构化摘要**

## 三类评论格式

### 决策评论

```
[决策] <主题> | <日期>

背景
- 为什么需要此决策

可选方案
- 方案 A：<描述>
- 方案 B：<描述>（已选/排除）

结论
- <选择了哪个方案>

依据
- <为什么选这个方案>

影响
- <影响范围>
```

### 审计评论

```
[审计] <审核点> | <日期>

审核项
- <审核内容>

结果
- 通过 / 不通过

依据
- <逐项核对结果>

打回原因（仅不通过时）
- <具体原因>
```

### 改进评论

```
[改进] <主题> | <日期>

来源
- 决策 / 审计

动作
- <需要做什么>

目标阻塞项
- <关联的阻塞项编号>
```

## 示例

```
[决策] 周报格式采用 Markdown | 2026-08-19

背景
- 周报格式需要统一，目前各人格式不一

可选方案
- A. HTML 表格（维护成本高）
- B. Markdown（已选，团队已有使用习惯）
- C. 富文本（编辑器集成成本高）

结论
- 采用 Markdown 作为周报输入标准

依据
- 团队已有 Markdown 使用习惯
- 实现成本低，不需要额外编辑器

影响
- 汇总解析逻辑基于 Markdown 语法
```
