# 过程审计的双会话设计（执行方式）

> 日期：2026-08-19
> 状态：草案，待讨论确认
> 前置文档：[process-audit-design.md](process-audit-design.md)（过程审计想法）— 本文档记录其**执行方式**
> 背景：过程审计需要独立于制作过程，会话隔离是解决「监督者被制作上下文污染」的执行方式选择

---

## 1. 定位

本文档记录**过程审计的执行方式**——如何在工作流中实现「独立监督、发现过程可优化环节」。

过程审计 ≠ 门禁：
- **过程审计**（本文档）：监督过程 → 发现可优化环节 → 产出过程优化建议
- **门禁**（另文档）：PO 验收产出物 → 放行/打回

本双会话设计是**过程审计**的执行载体，不承担门禁的放行/打回职责。

---

## 2. 设计约束

- **问题**：监督者若与制作过程共享上下文（同一会话、同一模型），会被制作过程污染，失去独立判断
- **解法**：会话隔离——制作实例与监督实例完全独立，彼此不共享模型状态与讨论上下文
- **选择依据**：文件系统桥接在 DSH 上零插件、零源码修改即可实现，仅需 skill 指令 + AGENTS.md 规范

---

## 3. 双会话架构

```
┌─────────────────────────────┐     ┌─────────────────────────────┐
│  副手会话（制作）              │     │  监督会话（过程审计）         │
│  负责：打磨讨论 + 执行开发     │     │  负责：监督过程 + 发现优化点  │
│                              │     │                              │
│  persona：开发副手             │     │  persona：过程审计者（独立模型）│
│  工具集：全量开发工具           │     │  工具集：gh + session-query  │
│  （bash/fs/gh/skill...）     │     │  （只读，无写文件权限）        │
└──────────────┬──────────────┘     └──────────────┬──────────────┘
               │                                   │
               │   ① 写入 checkpoint.json           │
               │   ───────────────────────────►     │
               │                                   │
               │             ② 人类切到监督会话       │
               │   ③ 拉取副手会话日志（session-query） │
               │   ◄───────────────────────────     │
               │                                   │
               │   ④ 写回 audit.json（过程优化建议）   │
               │   ◄───────────────────────────     │
               │                                   │
               │   ⑤ 人类切回副手会话，阅读审计结果    │
```

## 4. 文件系统桥接协议

两个会话通过**共享工作区**的文件交换状态，定义 `.ai-engineering/gate/` 目录：

```
.ai-engineering/gate/
├── checkpoint.json      # 副手写入，监督读取（阶段完成信号）
├── audit.json           # 监督写入，副手读取（审计结论 / 过程优化建议）
└── sessions/
    └── <sessionId>.log  # 监督拉取的审计快照（可选）
```

**checkpoint.json（副手 → 监督）：**

```json
{
  "phase": "polishing",              // 当前阶段：polishing / execution
  "step": "review-ready",            // 阶段内进度
  "goalIssue": 1,                    // 关联 Goal Issue 编号
  "assistantSessionId": "sess-xxx",  // 副手会话 ID（供监督拉日志用）
  "summary": "打磨完成，方案已定稿",
  "createdAt": "2026-08-19T10:00:00Z"
}
```

**audit.json（监督 → 副手）：**

```json
{
  "type": "process-audit",           // 过程审计（区别于门禁验收）
  "goalIssue": 1,
  "findings": [                      // 过程中发现的可优化环节
    {
      "phase": "polishing",
      "issue": "方案讨论中出现 3 次重复返工",
      "suggestion": "引入方案对比模板，减少游离讨论",
      "severity": "medium"
    }
  ],
  "overall": "过程整体顺畅，存在少量可优化点",
  "reviewedBy": "supervisor-session",
  "auditedAt": "2026-08-19T11:00:00Z"
}
```

> 注意：`audit.json` 的产出是**过程优化建议**（findings），而非门禁的 approved/rejected。门禁的放行/打回由 PO 另走门禁流程。

**读写权限**：
- 副手会话：可写 `checkpoint.json`，只读 `audit.json`
- 监督会话：只读 `checkpoint.json`，可写 `audit.json`
- 通过 DSH preset 的 toolFilter（bash 限制在 `.ai-engineering/gate/` 目录内）实现

## 5. 监督审计流程（session-query 证据链）

DSH 的 `session-query` 服务（`load(sessionId)`）可读取指定会话的**完整事件日志**（包括 user/message、assistant/message、tool/call、tool/result）。监督 Agent 据此做证据链审计：

```
监督 Agent 的过程审计流程：
  ① gh issue view #N
     → 读取 Goal Issue 当前状态（了解过程进展）
  ② session-query load <副手会话ID>
     → 拉取副手完整讨论日志（真实过程，非 AI 记忆）
  ③ 分析过程质量：
     - 环节顺畅度 → 是否有停滞 / 重复讨论
     - 决策效率 → 决策是否及时、依据是否充分
     - 返工迹象 → 是否反复推翻 / 重复劳动
     - 沟通清晰度 → 需求表达是否含糊、是否有误解
  ④ 产出 findings（可优化环节 + 优化建议）
  ⑤ 写 audit.json + 在 Goal Issue 追加审计评论
```

**副手会话的讨论日志本身成为不可篡改的审计证据**——这是 DSH 相比 GitHub Issue 原生流程的独特优势。

## 6. 人类在双会话间的角色

人类是双会话之间的**搬运工**：

| 节点 | 人类动作 |
|------|---------|
| 阶段完成 | 在副手会话确认完成，Agent 写 `checkpoint.json` |
| 触发审计 | 切换到监督会话，指令 "审计过程中文 checkpoint" |
| 审计执行 | 监督 Agent 拉日志分析（人类观察） |
| 审计结论 | 人类在监督会话审阅 `audit.json` 合理性 |
| 返回执行 | 切换到副手会话，Agent 阅读审计结论，落实优化建议 |

**副作用控制**：过程审计仅输出建议，不阻断制作流程（区别于门禁）。人类可决定哪些优化建议采纳、何时采纳。

---

## 7. 与状态机的衔接

过程审计**不驱动** Goal Issue 状态流转（放行/打回是门禁的职责）。审计是持续观测：

```
副手会话                         监督会话                     Goal Issue 状态
  │                                 │                             │
  ├─ 打磨进行中                      │                             │
  ├─ 写 checkpoint.json             │                             │
  │  (阶段完成信号)                  │                             │
  │                                 │                             │
  │                     [人类触发审计]                             │
  │                                 │                             │
  │                         ① 读 checkpoint                       │
  │                         ② 拉副手日志                         │
  │                         ③ 写 audit.json（findings）          │
  │                                 │                             │
  │                     [人类返回副手会话]                           │
  │                                 │                             │
  ├─ 读 audit.json ──────────────────────────────►（状态不变）
  │  落实优化建议，继续过程
```

> 状态流转（draft → reviewing → approved/rejected）由**门禁**驱动，见目标文档门禁章节。
