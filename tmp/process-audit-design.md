# 过程审计（独立于门禁）设计想法

> 日期：2026-08-19
> 状态：草案，待讨论确认
> 背景：澄清「门禁」与「过程审计」是两个不同概念，本文档记录**过程审计**的想法。

---

## 1. 概念定位

**过程审计 ≠ 门禁。** 两者长期被混淆，现拆分为两个独立概念：

| | 过程审计 | 门禁（Gate） |
|--|---------|-------------|
| **目的** | 监督研发**过程**，发现可优化的环节 | 验收**产出物**质量，保证最终软件质量 |
| **产出** | 过程优化建议 | 放行 / 打回 |
| **性质** | 审计行为（持续、观测、改进） | 管理动作（定点、验收、决策） |
| **关注对象** | 过程本身（环节顺畅度、浪费、返工、瓶颈） | 产出物（文档、方案、代码、测试结果） |
| **发起者** | 独立监督角色 / 审计者 | **PO（人类角色）** |
| **时间维度** | 持续（随过程推进） | 定点（每环节产出物完成后） |

## 2. 过程审计的目的

监督研发过程，回答三个问题：

1. **哪些环节在顺畅产出？** — 识别有效的流程环节
2. **哪些环节存在浪费或返工？** — 识别瓶颈、重复劳动、无效循环
3. **如何优化过程？** — 提出可执行的过程改进建议

本质上是「对过程的复盘与改进」，而非「对产出的验收」。

## 3. 过程审计的行为特征

- **观测**：持续观察研发过程（讨论、决策、执行、验收各环节）
- **发现**：识别过程中可优化的环节（效率问题、沟通问题、流程断裂）
- **建议**：产出过程优化建议，反馈给流程管理者（PO / 团队）

## 4. 与门禁的关系（边界明确）

```
研发过程： 打磨讨论 ──► 产出物A ──► 执行 ──► 产出物B ──► 交付
                │            │           │            │
            过程审计 ──►     门禁验收     过程审计 ──►  门禁验收
           （发现优化）   （PO 对照标准） （发现优化）  （PO 对照标准）
```

- **过程审计**横贯整个过程，持续贡献「过程优化建议」
- **门禁**发生在每个产出物完成后，由 PO 验收放行

两者互补：过程审计保证**过程**越来越好，门禁保证**产出**越来越稳。

3. 过程审计的**执行者**：人类角色？独立 Agent？监督会话？
4. 过程审计发现的问题如何进入**流程改进**闭环？
